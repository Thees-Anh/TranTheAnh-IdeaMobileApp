# Pet equipment and attachment rig

Apply `supabase/migrations/20261105001200_pet_equipment.sql` **once after 011**.
No service-role key belongs in the app. Buy an accessory first, then use
Inventory → Equip/Unequip. Pet Home renders the server-confirmed equipment.

## Persistence and ownership

`accessory_slots` maps catalog items to HEAD (hat), FACE (glasses), NECK (collar).
`pet_equipment` has one row per user/slot, a foreign key to the user's inventory
and a composite foreign key to the allowed item/slot pair. Catalog triggers keep
mapped items in the ACCESSORY category. Inventory constraints keep unique
accessory quantities at 1; owned equipped rows cannot be deleted underneath them.
Inactive but already-owned accessories remain equip-compatible.

Authenticated clients have SELECT-only access under RLS. They can read their own
equipment and slot metadata, but cannot write ownership or equipment directly.
`equipment_set(slot,item_id)` derives ownership from `auth.uid()`, serializes
changes on the wallet row, validates slot compatibility and locks owned stock.
A null item ID unequips the slot. Repeated set/clear operations are idempotent;
they do not consume items, spend Coins or grant XP. `equipment_state()` restores
the current selection through an authenticated invoker-rights read RPC. All
stored timestamps are timestamptz instants; use explicit display timezones.

Shared EquipmentRepository, EquipItem and UnequipItem contain no rendering APIs.
InventoryViewModel publishes confirmed equipment through StateFlow; it disables
overlapping changes and preserves an ambiguous command for an exact setter retry.
Terminal ownership/slot rejections leave the previous appearance intact. Refresh
results started before a mutation cannot overwrite its confirmed state.
Equipment is loaded at startup, on resume and when opening Inventory. An
account-scoped CompositionLocal supplies the current list to the Android scene.
The selection persists on the server across process death, independently of GLBs.

## Actual cat inspected before attachment implementation

The bundled `models/cat.glb` has **no skins, joints or skeletal weights**. It has
38 nodes and five clips (Idle, Happy, Eating, Sleeping, Playing). All animation
channels target node 37, `Animation pivot`. Its child node 36, `Centered geometry`,
has translation `(0,-1.23,0)` and contains meshes with positions baked in cat
coordinates. A synthetic SceneView normalization root is separate from the pivot.

Attachments are native ModelNode children of `Centered geometry`. Filament's
transform hierarchy therefore moves them with the same pivot as the body, eyes
and ears. No per-frame delayed position copying or guessed bone indices are used.
The following origins use glTF units, +Y up, +Z toward the front:

| Slot | Origin under Centered geometry | GLB |
|---|---|---|
| HEAD | (0, 2.28, 0.06) | models/accessories/hat.glb |
| FACE | (0, 1.83, 0.56) | models/accessories/glasses.glb |
| NECK | (0, 1.31, 0) | models/accessories/collar.glb |

These are original simple development assets generated by
`python tools/assets/generate_dev_accessories.py`; they are not final art. Hat placement
preserves both ears; the collar is sized around the actual body/chest surface.
Accessory transforms stay at uniform scale 1 in the cat's authored units. They
inherit the same normalization and uniform animation scales as the cat.

## Asset contract and replacement rigs

Each accessory has a sibling `.attachment.json` containing slot, parent name,
position, exact cat GLB SHA-256 and an all-animation envelope in cat coordinates.
Android resolves only the three allowlisted logical asset IDs. File reads run off
the UI thread; native creation, parenting and release run on the main thread.
Unknown IDs, missing/corrupt files, missing transforms or a cat fingerprint mismatch
skip that accessory and show a preview-unavailable message. They do not unequip
the server selection or prevent other accessories/the cat from rendering.

Do not simply change the fingerprint when replacing the cat. Inspect the new
hierarchy, skin/joint names, rest transforms, units and all clips first. Author
stable Head/Face/Neck socket nodes under the appropriate animated bones/transforms,
update the attachment resolver/metadata and test every clip. Rigid accessories
must be parented to the socket/bone transform. Deformable clothing requires a
compatible skinned mesh and verified bone bindings; this implementation does not
pretend the current rigid cat has such a skeleton. Do not parent accessories to
the static normalization root or apply skin transforms twice.

## Portrait framing and resource ownership

Metadata bounds include all accessory vertices under every current clip. The
generator bounds each vertex's distance from the pivot, multiplies by the maximum
uniform scale 1.025, and adds maximum translation 0.16 plus margin 0.05. This
rotation-invariant envelope covers intermediate rotations as well as keyframes.
The rig verifier checks that the actual cat still satisfies those assumptions.

PetSceneView unions accessory envelopes with the cat envelope around the existing
cat center, then recalculates distance and clipping planes using actual viewport
aspect. Equipping/resizing can move the camera backward; animation switches never
change camera aspect or object proportions. Unequipping restores cat-only framing.
Conservative framing can make the cat small in short compact scene panels.

Replacing or clearing equipment detaches accessory entities from the scene before
destroying their gltfio models. Scene destruction clears accessories before the cat,
then releases existing loaders/engine resources. Pausing leaves scene ownership
with the established lifecycle; resumed scene recreation reads confirmed equipment.

## Verification

- `python tools/validation/verify_accessory_rig.py`: inspect actual rig, clip scale/translation
  limits, attachment fingerprints and every accessory vertex's analytic envelope.
- The locally available Khronos glTF validator checks generated files; all three
  development GLBs have zero errors and warnings.
- `python tools/testing/test_database.py`: two fresh migration replays, slot/ownership/RLS,
  repeated setters, protected inventory and concurrent equip/unequip tests.
- `./gradlew :shared:testAndroidHostTest :androidApp:assembleDebug :androidApp:lintDebug`:
  repositories, confirmed equipment state/restoration/retry and portrait frustum tests.
- Local emulator fixture `tools/testing/fixtures/equipment_http_fixture.py` is only a
  test double; SQL tests validate the real authorization rules. Never leave fixture
  URL/key settings in local.properties or ship a fixture-backed APK.

Manual live-project check after applying migration 012: buy each accessory,
equip all three, return to Pet Home, try all clips, restart the app and verify
restoration. Unequip each item and verify it disappears without changing inventory
quantity or wallet balance. Test a missing accessory file in a development build,
then restore it. Replacing a rig requires new attachment/framing verification.
